carla_ws  -  CARLA 0.9.15 playground: NPC control, scene recording/replay, closed-loop driving baselines in sync, and
             a map-to-simulator pipeline that rebuilds any real place as a drivable CARLA scene.
=====================================================================================================================

This repository holds CODE ONLY. Nothing here is a dataset, a checkpoint, a simulator binary or a rendered output.
Everything below the "What is NOT in this repo" section has to be fetched separately; the paths the scripts expect
are listed there. COMMANDS.txt is the operational manual (every launcher, every flag, every gotcha, in the order the
work was done). This file is the map of the repo plus the dependency list.

2. HOW THE PIECES FIT (what "controlling NPCs" and "syncing other algorithms" means here)
------------------------------------------------------------------------------------------
  * CARLA runs in synchronous lock-step (fixed_delta 0.05 s). A held ego stops the clock, so nothing in this repo uses
    wall-clock countdowns; a world left in sync mode with no ticker wedges the server, so every script resets async on exit.
  * NPCs are either Traffic-Manager vehicles with per-vehicle overrides (speed %, lane offset, distance) or vehicles we
    drive directly with set_target_velocity / apply_control from a recorded track (npc_tracks). Pedestrians are driven
    with WalkerControl along polylines; gestures are bone poses (Walker.set_bones + blend_pose).
  * Baselines (TCP, CaRL/Think2Drive, BridgeDrive(LEAD), SimLingo, DrivePi0/DriveMoE, WA-JEPA, PDM-Lite expert) all run
    through the Bench2Drive leaderboard evaluator, each on its own CARLA port and conda env. Our scenario patches
    (object_crash_vehicle.py etc.) add: HoldEgoUntilFlag (start on key press), EndAfterScene (flag file read by the
    patched scenario_manager), TrackReplayer (replay a recorded NPC track inside a scenario), scenario knobs via the
    SCENARIO_OVERRIDES env (cut-in distance, speed) - see COMMANDS.txt "CUSTOM SCENARIO KNOBS".
  * The human agent (Bench2Drive/leaderboard/team_code/human_b2d_agent.py) lets you drive a scored route yourself with
    the route shown as dim dots plus a bright marker 20 m ahead.


3. REAL-WORLD SITE PIPELINE (geo_scenes/)
------------------------------------------
  python geo_scenes/site_app.py                    -> http://localhost:8765 : search, click, BUILD (~1 min), DRIVE
  python geo_scenes/build_site.py NAME LAT LON     -> same build from the shell
  ~/miniconda3/envs/b2d/bin/python geo_scene.py --site geo_scenes/NAME [--cars 30 --walkers 60] [--test] [--no-marks]

  build_site.py      OSM via Overpass (ways + multipolygons), ESRI World Imagery z19 (0.23 m/px), then the steps below
  detect_sat.py      SAM3 text prompts on the image: cars (pose, size, heading), trees (crown), lot/grass/water/building masks
  build_xodr.py      OSM -> OpenDRIVE with carla.Osm2Odr (service roads + parking aisles included) ->
  fix_xodr.py          sanitizer: roads <1.5 m stretched, crosswalk objects past the road end removed (both segfault the
                       server), SUMO "restricted" lanes -> driving, junction sidewalk lanes narrowed to 1 cm (CARLA ignores
                       <height> there and would put a 15 cm kerb across the turning area)
  add_parking.py       lot polygons (OSM + satellite masks) paved as 9 m "parking" lane strips at the exact road elevation
  estimate_heights.py  building heights from roof parallax when OSM has no height tag (needs 3 tagged buildings)
  geo_scene.py       generates the world live, builds every footprint from CARLA's own cooked meshes (church / apartment /
                     house meshes, storey modules for large buildings, podium+towers from building:part, columns+deck+store
                     for a store tagged layer>=2 with aisles under it), trees at detected crowns, parked cars snapped to a
                     bay grid (2.7 m pitch) with painted bay lines, lane dashes, shop-front props, lamps, TM traffic,
                     pedestrians on OSM footways, satellite minimap HUD
  aerial.py, photo.py, gen_test.py, make_pipeline_figures.py     QA captures and the figure set for the README
  geo_assets.json    measured sizes/pivots of the CARLA meshes used (spawned by path with static.prop.mesh)
  osmutil.py         OSM parsing incl. multipolygon rings

  Known limits: parallax displaces tall roofs from footprints in the imagery (the footprint is right); lanes come from OSM
  lane counts (3.5 m default); no grass/water material can be spawned; garage interiors are generated, not observed.

---------------

    GPUs: see README.md), ffmpeg 8, conda (miniconda3 at ~/miniconda3; all launchers use absolute env paths).

    simlingo   py3.10  torch 2.8+cu128, transformers 4.46, carla 0.9.15 (+ transforms3d py-trees==0.8.3 dictor ephem
                       simple-watchdog-timer filterpy rdp)                     -> SimLingo and the PDM-Lite expert

7. QUICK START
--------------
  bash carla_server.sh &                                                   # server on :2000
  ~/miniconda3/envs/b2d/bin/python geo_scenes/site_app.py                  # or any scene script, e.g.
  ~/miniconda3/envs/b2d/bin/python parking_lot.py
  bash run_simlingo_eval.sh 24211                                          # a baseline on a Bench2Drive route
  bash tour44_drive.sh 5                                                   # drive scenario type 5 yourself
  bash stop_all.sh                                                         # always stop the server after tests (GPU)
  Everything else: COMMANDS.txt.
